# Orrery Open Builds

**Fewer tools. Clearer outcomes.**

Each quarter, Orrery plans to release one small, independently useful open-source project. Each should replace a repeated manual check, a duplicate workflow, or an extra tool a team has to open. The test is whether someone can use it without paying us or giving us their data.

## 2027 roadmap

| Quarter | Build | Job it should take off your plate | Status |
|---|---|---|---|
| Q1 | [Request Proof Kit](projects/request-proof-kit.md) | Count a confirmed request once, even if it arrives twice. | Planned |
| Q2 | [Outcome Proof Scorecard](projects/outcome-proof-scorecard.md) | Compare work by verified results instead of activity. | Planned |
| Q3 | [Handoff Reconciler](projects/handoff-reconciler.md) | Find missing, duplicate or conflicting records across two exports. | Planned |
| Q4 | [Vendor Exit Drill](projects/vendor-exit-drill.md) | Check that a neutral export can be used by a replacement tool. | Planned |

This is a roadmap, not a software release. Project code and its license will appear with each reviewed release. Project scopes may change if the work does not remove a step people actually need to remove.

## What qualifies for release

A fresh install must run a synthetic example and produce an outcome a second person can check. No account or collection of usage data by default. We will publish the steps, known limits, and examples that fail as well as ones that pass.
